**Describe a major decision that you made early in your project/achievement, and how it affected that project/achievement down the line. Was it the right decision? Why? 200 words max**
In my search engine Sift I decided to design the crawler around a system that had a concurrent map of hostnames to buffer queues. Each buffer queue would contain information about the host and a queue of urls to be crawled. Go channels were created based on the number of crawlers I want running at once. One a url finished crawling, it would lock the host for a few seconds to prevent DDos-ing.  This was not the right decision because if there was a popular host like google.com that had many urls then it would clog up my pool of hosts and stay there. Newer hosts that wanted to get into the pool could not because the pool was held up by hosts that were waiting on cooldowns. I had it set that only when a host is off cooldown and has no urls waiting to be crawled that then it could be removed from the pool. I ended up refactoring the crawler to use a separate cooldown heap that would keep track of which host is about to be off cooldown, then the hosts pool could keep up with the influx of urls wanting to be tracked.
